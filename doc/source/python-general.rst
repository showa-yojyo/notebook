インストール・更新・アンインストール
--------------------------------------------------------------------------------

サードパーティー製のパッケージをインストール・更新・アンインストールする手順は
|uv| を利用しているか否かでしか違いがないようだ。

|uv| を利用可能である場合
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

PyPI などの配布拠点で純粋な wheel ファイルで配布されているなど、一般的な形態で対
象パッケージが入手できるならば、|uv| を用いてインストール・更新・アンインストー
ルするのが今のところ最善であると考えられる。

他の管理プログラムとは異なり、対象パッケージの用途に応じて |uv| の最適操作を見極
めろ：

* サードパーティー製パッケージを CLI として使う場合
* 独自スクリプトがサードパーティー製パッケージに依存する場合
* 独自プロジェクトがサードパーティー製パッケージに依存する場合

サードパーティー製パッケージを CLI として使う例としては、私の観測範囲内では次の
ものが相当する：

* コード検査プログラム (e.g. mypy, Pylint, Ruff)
* 試験援助プログラム (e.g. pytest, Coverage.py)
* 変換プログラム (e.g. MkDocs, Sphinx)
* アプリケーション (e.g. IPython, yt-dlp)

いずれの方法も |using-uv| で記した手順に従え。

|uv| 以外を利用する場合
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

|uv| 以外のパッケージ管理プログラムを採用している場合、サードパーティー製品のイン
ストール・更新・アンインストール方法は管理プログラムやパッケージによらず、ほとん
ど同一だ。共通手順をここに記す。

PyPI_ に識別子 ``PKG_NAME`` で登録されている Python パッケージをインストールする
には、使用している管理プログラム (:program:`pip`, :program:`conda`,
:program:`mamba`) に応じて、シェルで次のように実行する：

.. sourcecode:: bash
   :caption: インストール命令例

   pip install PKG_NAME
   conda install -n ENV_NAME PKG_NAME
   mamba install -n ENV_NAME PKG_NAME

ここで、``ENV_NAME`` とあるのは、管理プログラムが認識可能な仮想環境の名前とす
る。上の例で ``ENV_NAME`` が見えないものについては、呼び出し時点で活動中の仮想環
境が対象となるか、システムに ``PKG_NAME`` がインストールされることになる。

また、実践ではさまざまなオプションや semantic version 指定が加わるはずだ。

更新、削除についても対応する道具の更新、削除命令を実行しろ。おそらく ``update``,
``upgrade``, ``remove``, ``uninstall`` のような名前の命令があるはずだ。
